# Pre-submission review — 2026-11-14

Scope: the store app and the admin console on `feature/admin-parity` (which contains `feature/web-parity`), reviewed from four angles: connectivity and resilience, security and privacy, retention and App Store performance, and UI/UX consistency. Findings were produced by four independent passes and each high-severity item was re-verified against the code. Line numbers are as of commit `d23301d`.

Verdict: the app is in good shape for a first submission. Nothing here is a hard App Review blocker, but three groups should be fixed first: one false claim in the review notes, three online reconnect gaps that turn a lock screen into a dead game, and two small bugs users will hit in the first session (the haptics toggle does nothing, and "Log in" after email verification does nothing if Profile is already open).

## 2. Should fix for 1.0 (user-visible, mostly small)

**Connectivity**
- 5xx/429/HTML proxy errors surface as "The operation couldn't be completed. (SquareOffNet.APIError error 0.)". `RoomCoordinator.describe` (`RoomCoordinator.swift:563-583`) only maps timeouts and known detail codes; `APIError` is not `LocalizedError`. Map status ≥ 500 and 429 to plain sentences, add a generic fallback.
- Cancel during an in-flight quick match or leave during host/join is ignored: the task completes and drags the user back into matching or a room, or toasts "Couldn't create the room" after a deliberate leave (`RoomCoordinator.swift:131-207, 231-250`). Use a generation counter bumped by `leave()`/`cancelQuickMatch()` and check it after each `await`.
- A signed-in user is shown as a guest whenever `restore()` fails for a non-401 reason (offline at launch), and the guest identity is handed to the room coordinator (`AccountStore.swift:181-185`, `ProfileView.swift:30-46`). Keep the previous signed-in value on non-401 failures.
- Waiting room shows a green "Connected" chip throughout a lobby reconnect, and the start watchdog says "Try starting the game again" while the button is disabled (`WaitingRoomView.swift:150-160, 215-240`, `RoomCoordinator.swift:217-229, 536-547`). Add a reconnecting state and a `cancelStart()`.
- Quick-match polling fails on the first bad poll and orphans the ticket (`RoomCoordinator.swift:481-497`). Tolerate ~3 failures and cancel the ticket on failure/timeout.

**Navigation and sheets**
- Three navigation chromes coexist: pill `BackButton` with hidden bar (Home, Play, Stats), a visible empty system bar (Profile `ProfileView.swift:61-62`, Rules `RulesView.swift:29-30`, leaving a blank strip above the heading), and the waiting room with a system title and no back control at all (`WaitingRoomView.swift:28-31`). Hide the bar on Profile and Rules; give the waiting room a "Leave" pill. Stats' button should read "Profile", not "Back".
- Every sheet has different close chrome, and the in-game Rules sheet has no close affordance (`GameView.swift:75-78`). Only the game menu shows a drag indicator. One `SheetHeader(title:onClose:)` primitive, used everywhere.
- The game menu presents Rules/Feedback on top of itself without dismissing first (`GameSheets.swift:73-78`); Reset/Leave already use the `pendingExit` pattern. Do the same for the other two.
- "Discard" on the Continue card is instant and irreversible (`PlayView.swift:249`); every other destructive action confirms.

**Forms**
- Join-code validation can never appear: the error is gated on `joinTouched`, set only in `onSubmit`, and the number pad has no return key (`OnlinePanel.swift:93-100`). Set it on first edit and add a keyboard "Done" toolbar.
- No `submitLabel`, `@FocusState` or keyboard toolbar anywhere; the sign-in password field has no `onSubmit` (`SignInView.swift:155-157`). Content types are already correct.

**Copy and consistency**
- Button casing drifts between Title Case ("Start Game", "Create Room", "Find a Match" in `PlaySetupModel.swift:114-120`) and sentence case ("Start game", "Play again", "New game"); "Quick match" vs "Quick Match"; "Vs Computer" / "Play vs Computer" / "vs CPU"; "Sign in to keep…" above a "Log in" button; toast "Logged in" vs "You've been signed out". Pick sentence case and "Log in / Log out" throughout.
- Setup forgets level, board, timer, player count and Pass & Play names between games (`PlayView.swift:12-17` builds a fresh model on every push). Persist the last setup and the guest's name/colour.
- Game Over share text has no link (`GameSheets.swift:289-292`). Append `https://square-off.com`.

**Accessibility**
- Rules prose is fixed 15pt, chips fixed 12pt, player names in row/result cards fixed 14pt (`RulesView.swift:218,250,263`, `Primitives.swift:101`, `GameChrome.swift` PlayerIdentity/SeatTag). Use text styles or `relativeTo:` as `Theme.display` already does.
- Tap targets under 44pt: toast dismiss 28pt, sheet X 32pt, history/pagination 32pt, compact segments 32pt, level picker 36pt. Keep the glyphs, enlarge the hit area.

**Store listing**
- Keywords repeat "strategy" and "shapes" (already in name/subtitle) and include "puzzle", which misdescribes a 2–4 player board game. Suggested: `abstract,tactics,2 player,4 player,pass and play,online,multiplayer,family,friends,duel,tiles,board`.
- Screenshot order leads with the static Home logo and then a 12×12 "busy" board that reads as noise at thumbnail size (`scripts/store-screenshots.sh:50-59`). Lead with a clean mid-game 8×8 scoring moment, then Pass & Play, then the online room.
- No first-time "How to play" nudge: Home shows two buttons and a demo board; the rules live only in the Learn tab and the in-game menu. A one-time tertiary link on Home plus a first-game coach line is cheap.

## 3. Security and privacy (none blocking)

- **Keychain outlives uninstall.** Tokens use `AfterFirstUnlockThisDeviceOnly` (`TokenStore.swift:44`); iOS keeps generic-password items across delete/reinstall, so a handed-down device opens signed in as the previous owner. Clear both token stores on first launch when an `installGeneration` UserDefaults marker is missing. Medium.
- **OAuth callback carries the full JWT in a custom-scheme URL and `state` is never checked** (`AccountStore.swift:291-297, 339-348`, `SignInView.swift:397-399`). Move to `ASWebAuthenticationSession.Callback.https` with a one-time code exchanged over the app's session and verify `state`. Needs a server change. Medium, hardening.
- Turnstile `WKWebView` allows any main-frame navigation and accepts `{token}` from any frame (`TurnstileView.swift:59-83`). Allow-list square-off.com and challenges.cloudflare.com; require main frame. Low.
- Deep links auto-join rooms and open reset/verify sheets without confirmation; the https branch accepts `http` and any host (`DeepLink.swift:38-49`, `AppModel.swift:128-141`). Require https + known hosts; confirm "Join room 12345?" when the code came from a URL. Low.
- `signedInWithApple` is a local flag, not server truth (`AccountStore.swift:240-250`), so after a reinstall account deletion skips the Apple re-authorisation. Expose `auth_provider` on the profile. Low.
- Mock demo credentials are compiled into the Release binary via `SquareOffNet` (`MockSquareOffAPI.swift:12-37`); unreachable at runtime (verified), but string-scanner noise. Wrap in `#if DEBUG` or split a mock product. Low.
- Feedback appends device model and OS version; the form discloses it and the privacy manifest is accurate. Optionally add "Diagnostics" to the App Privacy answers. Informational.

Verified fine: developer switcher and mock backend are `#if DEBUG`/`fatalError`-gated in Release, no token/email logging, ATS default, entitlements minimal, Sign in with Apple parity, native two-step account deletion, no login wall, privacy manifest matches collection.

## 4. 1.1 backlog (retention)

- No reason to come back yet: no Game Center achievements or leaderboards, no notifications, no streaks, no rate prompt (all verified absent). Cheapest first steps: achievements driven from the existing end-of-game path, a "Next: try Level N+1" button after a CPU win, `requestReview` after the third completed game.
- Game Over has no bridge to Stats or Replay, and no sign-up prompt for guests at the moment they most want to keep the game (`GameSheets.swift` footer; `recordedGameID` is already known).
- Default palette pits red against green in a 2-player game (`Theme.swift:41`), and shapes are distinguished by colour only. Consider purple for seat 2 or a pattern/initial option.
- Levels 7–8 on a black-holed network pay the full 8 s timeout and show the fallback notice on every CPU turn (`ServerCPUMoveProvider.swift:24-44`). Add a per-game circuit breaker and `postOnce`.
- Request and handshake timeouts: `URLRequest.timeoutInterval` defaults to 60 s and overrides the session's 15 s (`RESTClient.swift:62`, `LiveGameSocket.swift:34-43`). Set it explicitly.
- Rejoin failure copy leaks server codes ("Couldn't rejoin (player_not_found)") and misattributes the user's own seat after a guest re-mint (`OnlineGameSession.swift:278-287`).
- Haptics/sound coverage is uneven (no feedback on segment/colour selection, invite copy or game over).
- Replay screen uses system idioms (`ContentUnavailableView`, full-width secondary buttons) unlike the rest of the app (`ReplayView.swift:30-32, 79-103`).
- Profile: "Log out" sits in the Preferences card while a separate card is titled "Account" (`ProfileView.swift:315-318`).
- iPad: phone detents are ignored, so the colour picker becomes a mostly empty form sheet (`ColorPicker.swift:24,88`).
- Localisation: all copy is inline with English grammar in interpolations; add a String Catalog before the string count grows.

## 5. What is already strong

- Session recovery is coherent end to end: one retry on `session_required`, user tokens never silently replaced, socket handshake applies the same policy, concurrent guest mints deduplicated.
- Local play never blocks on the network; server CPU levels fall back to on-device with validated replies; the recorder disables itself after one failure with a single notice.
- A real button system and consistent primary/secondary/tertiary hierarchy; online flows have loading, error and empty states; destructive confirmations with role-aware copy.
- Zero-friction first game (two taps as a guest), auto-saved local games, complete online loop with room codes, share links and universal links, rich Game Over sheet with a score chart.
- iPad is first-class (sidebar layout, adaptable tabs, all orientations) and the store package (metadata, privacy manifest, review notes, age rating, screenshot script) is unusually complete for a first submission.
- Release/Debug separation is thorough and self-checking (`release-check`, Debug-only entitlements twin, mock unreachable in Release).
